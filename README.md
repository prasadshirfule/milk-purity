> ### ⚠️ Scientific & Engineering Notice
> **Automated Quality-Screening Estimate Only. Not a certified laboratory chemical assay.**
> MILKGUARD evaluates multi-parameter sensor readings (pH, estimated fat, density, electrical conductivity, temperature) against user-configured reference bounds. The **Milk Purity Score (0–100%)** and **AI Recommendations** are generated by the baseline quality screening engine (`screening-baseline-v1`). They do not substitute official certified dairy laboratory chromatography or regulatory food safety assays.

---

## 📌 Project Overview

**MILKGUARD** is an end-to-end IoT-ready dairy quality assurance and procurement ledger platform built for rural milk collection centers, co-operatives, and dairy processing units. It captures multi-sensor telemetry (simulated in Demo Mode, ready for ESP32 hardware in Connected Mode), calculates an authoritative **Milk Purity Score (%)**, provides **AI/ML Recommendations (`ACCEPT` / `REVIEW` / `REJECT`)**, enables transparent farmer procurement payouts in Indian Rupees (₹), tracks supplier ledger accounts, detects parameter anomalies, and maintains a complete audit trail for operator overrides.

### 1. Canonical ESP32 Telemetry Contract (`POST /api/devices/:deviceId/telemetry`)
Physical ESP32 hardware docks or the development simulator dispatch HTTP POST JSON telemetry payloads conforming to:

```http
POST /api/devices/ESP32-MILK-001/telemetry HTTP/1.1
Host: localhost:5000
Content-Type: application/json
X-Device-Key: dev_sec_esp32_milk_001_live

{
  "deviceId": "ESP32-MILK-001",
  "timestamp": "2026-09-07T10:30:00.000Z",
  "temperature": 24.2,
  "ph": 6.65,
  "fat": 4.5,
  "density": 1.029,
  "conductivity": 4.8,
  "milkLevel": 25.5,
  "firmwareVersion": "v2.1.0",
  "sequenceNumber": 1042,
  "batteryLevel": 98
}
```

### 2. Secure Device Authentication (`X-Device-Key`)
- **Header-Only Ingestion**: Telemetry requires `X-Device-Key: <secret>`. Insecure query parameters (`?apiKey=...`) and body credentials are not permitted.
- **Leakage Prevention**: Device API keys are never exposed in `GET /api/devices` or `GET /api/devices/:id`, never stored in frontend state, and never saved in audit logs.
- **One-Time Provisioning**: When registering a device, the backend generates a secret key (`dev_sec_...`) returned once with instructions to flash it onto the microcontroller.

### 4. Arduino / C++ Firmware Skeleton (`/esp32`)
Production-ready firmware skeleton is located at [`esp32/milkguard_esp32_firmware.ino`](file:///e:/MILK-PURITY/esp32/milkguard_esp32_firmware.ino) with pinout wiring guide in [`esp32/README.md`](file:///e:/MILK-PURITY/esp32/README.md):
- Modular sensor abstraction functions (`readTemperature()`, `readPH()`, `readFat()`, `readDensity()`, `readConductivity()`, `readMilkLevel()`).
- WiFi auto-reconnect and non-blocking `millis()` sampling loop.
- `X-Device-Key` header injection and JSON serialization via ArduinoJson.

### 5. Sensor Validation vs Quality Scoring Separation
- **Sensor Validation Layer (`SensorService`)**: Validates physical plausibility bounds (temperature -10 to 100°C, pH 0–14, fat 0–20%, density 0.5–2.0 g/mL, conductivity 0–50 mS/cm, milkLevel ≥ 0) and rejects `NaN`, `Infinity`, and malformed payloads. Missing sensor values never silently become zero.
- **Sequence & Idempotency Protection**: Ingests newer sequence numbers (`200 ACCEPTED`), recognizes duplicate sequence packets (`200 DUPLICATE`), and rejects older out-of-order packets (`409 OUT_OF_ORDER`).
- **Quality Screening Layer (`QualityService`)**: Computes the authoritative Milk Purity Score (0–100%) and screening recommendation.
- **Telemetry Ingestion ≠ Milk Test**: Telemetry packets update device snapshots and heartbeat status only. A Milk Test is created exclusively when an operator executes a test for an identified customer.

### 6. Deterministic Device Status Rules
- `UNKNOWN`: Device has never received telemetry (`!lastSeen`).
- `ONLINE`: Valid telemetry received within configured timeout (60 seconds).
- `OFFLINE`: Device previously reported telemetry but timeout (> 60 seconds) has elapsed.
- `WARNING`: Device is online but one or more sensor probes require attention.

## 🌟 Key Functional Modules & Architecture

1. **📊 Main Operational Dashboard (`/dashboard`)**:
   - 8 live KPI summary cards: Total Farmers, Today's Intake (L), Accepted Milk (L), Rejected Milk (L), Revenue (₹), Average Estimated Fat %, Average Milk Purity Score (%), and Active Alerts.
   - Quality screening distribution overview (`ACCEPTED`, `WARNING`, `REJECTED`).
   - Dynamic intake volume area chart computed directly from recorded collection logs.
   - Dedicated **Milk Purity Score Screening Trend (%)** chart.

2. **👨‍🌾 Farmers Registry & QR Customer Identification (`/farmers`, `/farmers/:id`)**:
   - Unique permanent Customer Codes (format: 1 uppercase letter + 4 digits, e.g. `A1024`).
   - Instant Customer QR generation, scanning, and fast intake preselection.
   - Lifetime volume, payout in ₹, purity score average, test history, and ledger statements.

3. **🥛 Milk Testing Station (`/milk-testing`)**:
   - Live Sensor Panel with 6 parameters and parameter health badges (`NORMAL`, `WARNING`, `INVALID`, `NO DATA`).
   - "Capture Sensor Snapshot" freezes the exact telemetry reading into the test record (`deviceId`, `sensorTimestamp`, `testTimestamp`, `temperature`, `pH`, `fat`, `density`, `conductivity`, `milkLevel`).
   - Authoritative **Milk Purity Score (0–100%)** radial gauge with classifications (`EXCELLENT`, `GOOD`, `WARNING`, `POOR`).
   - Prominent **AI/ML Recommendation Banner** (`ACCEPT`, `REVIEW`, `REJECT`).
   - Operator decision workflow (`ACCEPT` / `REJECT`) with mandatory audit reason capture for manual overrides.

4. **📜 Test History & Audit Trail (`/history`, `/audit`)**:
   - Multi-filter search (date range, customer code, result status).
   - Immutable audit logs capturing operator actions, overrides, and device provisioning.

5. **📦 Milk Collections & Payments Ledger (`/collection`, `/ledger`)**:
   - Centralized dairy procurement ledger linking accepted tests to collection records.
   - Rejected batches enforce ₹0 payout and do not create collections.

6. **📡 IoT Devices & Analyzer Nodes (`/devices`)**:
   - Real-time probe and dock status for ESP32 testing stations.
   - Admin-only device registration, update, and deactivation.
   - Clearly labeled **DEMO SENSOR DATA** (simulated) vs **CONNECTED HARDWARE** (live telemetry).

## 🏛️ System Architecture

```
Physical / Simulated ESP32
  ↓ [POST /api/devices/:deviceId/telemetry]
Sensor Validation Layer (Plausibility checks, no zero fallbacks)
  ↓
Device Snapshot Cached & Heartbeat Updated (Deterministic Status: ONLINE/OFFLINE/UNKNOWN)
  ↓
Operator clicks "Capture Sensor Snapshot" + Customer QR Scanned
  ↓
Frozen Sensor Snapshot (sensorTimestamp, testTimestamp, parameters)
  ↓
QualityService & ML Baseline Screening (Milk Purity Score 0–100% + AI Recommendation)
  ↓
Operator Decision (ACCEPT / REJECT + Override Reason if overriding REJECT)
  ↓
Database Persistence (MilkTest, MilkCollection if accepted, Audit Log)
```

## 🔬 Scientific Limitations & Roadmap

1. **Scientific Boundaries**: Sensor-based screening flags deviations in conductivity, density, pH, and optical turbidity. Definitive determination of complex synthetic adulterants (e.g. melamine, detergent) requires laboratory spectrometry.
2. **TinyML Edge Inference**: Future integration will port quantized ONNX/TensorFlow Lite models directly to ESP32-S3 boards.
3. **Automated Thermal Printing**: Direct ESC/POS dock receipt printing for instant farmer delivery slips.
